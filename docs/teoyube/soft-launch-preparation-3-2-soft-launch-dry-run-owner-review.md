## What This Step Adds

This step rehearses the limited soft launch process without launching Teoyube, contacting real users, collecting real feedback, fetching preview URLs from code, writing files, writing databases, sending analytics, or calling external services.

It adds:

- Dry run contracts

- Dry run runner

## Dry Run Scenario Matrix

The scenario matrix covers preflight, launch day, surface review, feedback intake, issue triage, rollback, daily review, owner review, and completion review.

It includes rehearsal scenarios for:

- Owner confirmation of limited scope
- Disabled external analytics
- Disabled production persistence
- Disabled live AI orchestration
- Scripture anchoring
- Explanation paths
- Fallback behavior
- Consent controls
- Manual preview URL review
- Canon, Daily Word, Prayer, Calling Compass, Promise Cluster, AI Companion, and Onboarding surface checks
- Sample positive feedback
- Sample mobile, Scripture, explanation, fallback, consent, and privacy reports
- Low, high, and launch-critical issue triage
- Manual pause and rollback decisions
- Known limitation documentation

## Dry Run Runner

The dry run runner records rehearsal step and scenario results in memory only.

It tracks:

- Scenario results
- Step results
- Critical scenario coverage
- Warnings
- Blockers
- Dry run decision

The runner explicitly records that it performs no actual launch, contacts no users, collects no real feedback, fetches no preview URLs, writes no database, sends no analytics, calls no external services, writes no browser storage, and writes no files.

## Launch-Day Rehearsal

The launch-day rehearsal verifies:

- Launch day runbook exists
- Preview URL review remains manual
- Surface checks are ready
- Feedback workflow is ready
- Issue triage workflow is ready
- Rollback criteria are visible
- Owner review is ready
- No users are contacted by code
- No launch action is performed by code

## Feedback Intake Rehearsal

The feedback rehearsal uses sample feedback only.

Sample cases include:

- User says the Scripture was helpful
- User says the explanation path is confusing
- User reports a mobile layout issue
- User reports consent control confusion
- User reports fallback did not feel clear
- User reports privacy concern
- User asks whether personalization is tracking them

The rehearsal validates that sample feedback is sanitized, no raw sensitive text is stored by default, feedback is not sent externally, feedback is not written to a database, and feedback does not create hidden personalization.

## Issue Triage Rehearsal

The issue triage rehearsal validates sample handling of:

- Missing Scripture anchor
- Missing explanation path
- Unsafe fallback report
- Consent control issue
- Debug payload exposed
- Mobile blocker
- Accessibility blocker
- Privacy concern
- Build or preview app issue

Launch-critical issues are intentionally classified as blockers during rehearsal so the dry run proves the blocker path works.

## Rollback Rehearsal

The rollback rehearsal verifies:

- Rollback triggers are known
- Pause criteria are known
- Owner can decide pause or rollback manually
- Issue categories requiring rollback are documented
- No automatic rollback is performed by code
- No external provider command is executed by code
