# A11Y-001 - Lexicon alphabet options use an unsupported ARIA attribute

Owner-review request only. This is not an approval and implements no fix.

- Severity: **CRITICAL**
- Current status: **confirmed**
- Owner decision: **PENDING**
- Proposal hash: `11aef30ee50faf3b9c61b744bdb867dfeb1d0a8cafe3569a831f011d9cc52afe`
- Recommended decision: **APPROVE_RECOMMENDED_PHASE5C_FIX**

## Scope

- Routes: `/lexicon`
- States: `default`, `alphabet-filter-selected`
- Viewports: desktop-wide, desktop-standard, tablet-landscape, tablet-portrait, mobile, mobile-small
- Affected users: screen-reader users, speech-input users, users who rely on accurate role/state announcements
- WCAG 2.2 A/AA: 1.3.1, 4.1.2
- Parity classification: `shared_defect`
- Fix class: `PROTECTED_ATTRIBUTE_CHANGE`

## Before-state evidence

axe aria-allowed-attr; 156 audited-node occurrences across repeated cells; 27 stable alphabet controls use role=option with aria-pressed

- Current behavior: All 27 alphabet controls are role=option elements carrying aria-selected and the unsupported aria-pressed state; axe reports aria-allowed-attr in every audited Lexicon cell.
- Expected behavior: Each option exposes only states supported by the option role, with selection represented by aria-selected and no conflicting pressed state.
- Static rollback: app.js renderLexiconAlphaTabs emits role=option, aria-selected, and aria-pressed; the static click path re-renders the same invalid combination.
- Canonical Next: The captured approved markup contains the same combination, and LexiconPageController updates both aria-selected and aria-pressed after activation.

## Proposed minimal action

In Phase 5C, remove aria-pressed from every role=option alphabet control in the static renderer, approved captured markup, and Next state updater; retain listbox/option, aria-selected, labels, order, click behavior, and pixels.

Likely files:

- `app.js`
- `src/app/_lexicon/LexiconPageController.tsx`
- `src/app/_approved-source/approved-view-markup.generated.ts`

Protected contracts involved:

- `tests/visual/contracts/static-dom-contract.json`
- `tests/visual/contracts/original-static-visual-contract.json`
- `tests/visual/baselines/static-runtime/manifest.json`

## Expected impact

- Pixel impact: **none**
- DOM/ARIA impact: **attribute_only**
- Product behavior: Assistive technologies receive one valid selected state instead of conflicting pressed/selected states; filtering behavior is unchanged.
- Visual evidence required: **YES**
