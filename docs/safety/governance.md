# Safety governance

The Teoyube owner is the policy and release authority. Theology policy changes require owner authorization and qualified human theology review. Clinical, legal, financial, and crisis-resource statements require competent review within their professional/resource boundary. Automated agents provide implementation evidence only and cannot approve their own theology, threshold, resource, or release changes.

Every policy, taxonomy, dataset, evaluator, prohibited-claim registry, and resource-registry change must be versioned. The change record must state rationale, exact contract/fixture delta, false-positive and false-negative effects, Scripture/theology effect, privacy effect, rollback, reviewers, and owner decision. Safety-critical false negatives have zero tolerance. Failing cases cannot be deleted or weakened to pass.

Resource entries have a source, scope, language, verified date, review/expiry date, limitations, and status. The named human resource owner refreshes or removes them before expiry. Until reviewed production coverage exists, the provider returns generic local-emergency guidance.

Privacy-safe observability is allowlisted: topic detected, mode selected, prohibited claim blocked, citation failure, injection blocked, memory/tool denied, fallback used, and gate failed. Events may carry policy version, coarse topic/mode/result, and count only. Raw input, prayer, journal/reflection, user identity, session secret, prompt, citation request text, or crisis narrative is forbidden.

Rollback is a focused revert to the last passing version plus re-running all blocking gates. The owner owns any future live-AI kill-switch authorization. Prompt 17 defines the interface and runbook but does not connect a provider or enable a kill switch.
