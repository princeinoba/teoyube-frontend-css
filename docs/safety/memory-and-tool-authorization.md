# Memory and tool authorization

Prompt 16 remains authoritative. A memory read requires an authenticated server-authoritative session, same-user scope, an allowlisted explicit purpose, effective purpose-scoped consent, an available/non-revoked record, and minimum-necessary structured fields. Cross-user, deleted, revoked, expired, or forbidden profile fields are denied.

A durable memory write additionally requires explicit user confirmation and a separate pre-write authorization. A crisis disclosure is never automatically persisted and cannot become a permanent crisis or mental-health profile. Divine conclusions, calling as fact, promise fulfillment, or God's action cannot be stored as facts by the safety layer. Evaluation data is synthetic.

During composition, all state-changing tools are denied. Critical mode permits only `scripture.read` and `crisis_resource.read`; user/retrieved text cannot expand permission. A separate confirmed application action must recheck authentication, authorization, same-user scope, source validation, purpose, consent where applicable, audit requirements, and reversibility.

TIG remains read-only with respect to journey, journal, testimony, promise, and Book state. Safety composition performs no journey advancement, calling declaration, testimony publication, promise fulfillment, memory write, or Book promotion.
