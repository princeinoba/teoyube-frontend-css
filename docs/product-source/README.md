# Teoyube Product and Theology Source Documents

These owner-provided documents are normative product, data-model, and theological inputs for the recovery program:

- `TEOYUBE THEOLOGY CONSTITUTION V1.pdf`
- `TeoyubeSearch Framework.pdf`
- `Teoyube Promise Cluster Architecture.pdf`
- `Promise Clusters.pdf`
- `Teoyube Language Grammar and Lexicon Architecture.pdf`

They do not authorize visual redesign. Where a document describes new behavior, implement that behavior behind the original Teoyube interface and reuse the established DOM structure, CSS classes, page composition, cards, imagery, icons, animations, responsive behavior, and interactions.

## Product relationships to preserve

- TeoyubeSearch moves from search intent through Scripture, promise meaning, prayer, Teoyube language, assignment, and Book of the Saint.
- Promise Clusters connect Search → Scripture → Promise → Teoyube Word → Prayer → Assignment → Testimony.
- Teoyube language supports the formation sequence Revelation → Promise → Calling → Action → Testimony.
- Teoyube’s core journey is Promise → Prayer → Calling → Purpose → Testimony → Legacy.
- Scripture remains the highest authority. Teoyube may explain, organize, personalize, and apply Scripture without replacing or rewriting it.
- Only the user may record or finalize testimony; Teoyube may propose a candidate but may not declare fulfillment.

## Implementation rule

Use these documents to design typed domain contracts, exact Scripture retrieval, promise levels, cross-module orchestration, safety policies, and Teo Guide tools. Preserve the original UI structure and visual identity while upgrading behavior beneath it.

Interpretation precedence and owner-approval rules are defined in the repository root `AGENTS.md`.
