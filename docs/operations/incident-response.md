# Incident response

Prompt 21 defines testable procedures; it does not claim an assigned 24/7
on-call team.

The current accountable role is `Teoyube owner/delegate`. Before production,
that role must be replaced by named primary and backup responders with alert
destinations.

Incident priorities:

- P0: cross-user exposure, key compromise, fabricated displayed Scripture,
  unsafe critical guidance, or unauthorized durable action;
- P1: deletion failure, corpus/index corruption, provider or observability
  outage without safe fallback, or uncontrolled cost;
- P2: visual/performance regression or degraded optional capability with safe
  fallback.

For every incident:

1. Protect users and activate the deterministic or static fallback.
2. Disable the affected capability with its kill switch when applicable.
3. Preserve bounded logs, correlation IDs, commit, manifests, checksums, and
   timelines without copying private spiritual content.
4. Communicate verified impact and uncertainty; do not speculate.
5. Repair or roll back using the matching runbook.
6. Re-run the named verification before restoring service.
7. Complete a blameless review with cause, impact, control gaps, and owners.

Procedures are in `docs/operations/runbooks/index.md`. Production paging,
status-page access, counsel, notification duties, and breach timelines remain
deployment/legal dependencies.
