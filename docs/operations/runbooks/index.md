# Prompt 21 incident runbooks

Owner in this preview plan means `Teoyube owner/delegate`; no staffed on-call
team is claimed. Preserve only privacy-safe evidence: commit, correlation IDs,
reason codes, hashes, timing, affected partitions, and bounded sanitized logs.

| Incident | Trigger | Immediate action | User impact and safe fallback | Evidence and communication | Recovery and verification | Post-incident review |
| --- | --- | --- | --- | --- | --- | --- |
| Production rollback | Release health or invariant gate fails | Stop promotion; restore last owner-approved artifact and configuration | New changes unavailable; static canonical runtime remains available | Preserve release manifest, deployment ID, failing checks; owner communicates verified scope | Re-run recovery, security, critical journeys, parity, and readiness before any re-promotion | Root cause, rollback duration, missing preflight |
| Live-AI kill switch | Provider safety, privacy, cost, or availability breach | Set `TEOYUBE_LIVE_AI_ENABLED=false`; revoke provider traffic | Teo Guide uses deterministic response | Preserve reason codes, model/snapshot, safe traces, cost totals; notify owner/provider as appropriate | Offline Gate A, deterministic Teo Guide, then protected provider preview before re-enable | Routing, policy, budget, and consent gaps |
| Vector retrieval kill switch | Isolation, consent, relevance, or index integrity breach | Set `TEOYUBE_VECTOR_RETRIEVAL_ENABLED=false` | Lexical and deterministic retrieval remain | Preserve index version/hash, partition, denial codes; notify owner | Verify corpus, trust/consent filters, deletion propagation, Prompt 20 gate | Index lifecycle and partition controls |
| Key compromise | Key appears in source, logs, artifact, or unauthorized use | Disable capability; revoke/rotate key; preserve metadata without printing key | Provider or encrypted store may be temporarily unavailable; deterministic fallback | Preserve discovery time, safe key identifier, audit events; owner coordinates required notices | Secret scan, history/build scan, new key validation, old-key denial | Exposure path and rotation readiness |
| Unauthorized memory access | Read/write without active purpose consent or ownership | Disable memory writes; isolate affected store/session | Session-only journey remains; user memory unavailable | Preserve pseudonymous record/session IDs and authorization decisions; contact owner and affected users when required | Cross-user, consent, export/delete, encryption tests plus record audit | Authorization and consent control failure |
| Cross-user incident | Any record/vector can cross tenant boundary | Disable affected repository and vector path immediately | Deterministic public data only; no private continuity | Preserve safe actor/record IDs, queries as hashes, access decisions; escalate P0 | Isolation tests, repository audit, deletion/revocation verification | Scope, notification, partition design |
| Fabricated citation | Displayed quotation fails exact WEB validation | Stop generated path; show reference-only deterministic fallback | Quotation withheld until verified | Preserve reference, corpus checksum, validator output; owner communicates correction | Corpus checksum, exact retrieval, citation gates at 100% | Source path and validator bypass |
| Unsafe spiritual guidance | Divine certainty, coercion, calling destiny, harmful advice, or critical ordering failure | Disable live AI; use deterministic safety response | Safe limitations, Scripture, counsel, and appropriate emergency/professional support | Preserve reason codes and fixture ID, not private prompt; owner/safety delegate reviews | Gate A 100%, prohibited claims, sensitive-topic and tool tests | Policy/fixture coverage and human review |
| Stale crisis resource | Jurisdiction/resource no longer verified | Remove affected resource from active routing without inventing replacement | Generic emergency/professional-care fallback where safe | Preserve source URL/version and review date; communicate affected locale | Reverify official source and run crisis fixture routing | Review cadence and ownership |
| Provider outage | Timeout, quota, rate limit, or circuit breaker | Keep live path bounded; switch to deterministic fallback | Teo Guide remains available without live generation | Preserve provider status class, model, latency, circuit state, cost; status message is factual | Offline fallback and protected provider smoke after recovery | Timeout, retry, and redundancy policy |
| Cost spike | Budget denial or abnormal token/cost counter | Disable paid path; do not raise budget automatically | Deterministic fallback | Preserve aggregate tokens, cost, route/model, request counts; alert owner | Validate budget controls and owner-approved new cap if any | Routing, abuse, prompt/context size |
| Rate-limit exhaustion | Legitimate or abusive requests exhaust route/provider quota | Keep denial bounded; protect critical deterministic routes | Temporary retry guidance; core Scripture/safety remains | Preserve route, safe subject hash, limit bucket, retry time; notify owner on sustained event | Rate-limit tests, capacity review, abuse controls | Limit sizing and distributed limiter need |
| Index corruption | Manifest/hash/SQLite integrity or relevance gate fails | Deactivate candidate; keep last verified index or lexical fallback | Vector ranking unavailable or last verified index used | Preserve index manifest/checksum and failing shard; owner informed | Corpus/index checksum, activation/rollback, full Prompt 20 gate | Build/activation atomicity and backup |
| Corpus checksum failure | WEB manifest or archive checksum differs | Stop quotation/index build; do not repair by baseline update | Reference-only error/fallback; no unverified quotation | Preserve expected/actual hashes and source identity; notify owner | Corpus and quotation gates from owner-approved source | Source acquisition and immutable storage |
| Migration failure | Schema migration does not complete atomically | Stop writes and release; roll back using migration contract | Read-only/session fallback where safe | Preserve migration/version, transaction result, sanitized DB error | Repository migrations, export/delete, cross-user tests | Forward/backward compatibility |
| Data deletion failure | User-confirmed deletion does not propagate | Stop claiming completion; retry bounded jobs; block related exports if inconsistent | Inform user deletion is pending; no new use of affected data | Preserve request ID, layers, timestamps, reason code; notify owner/user | Deletion ledger, memory/vector propagation tests and record absence | Idempotency, queue/storage dependencies |
| Visual regression | Protected hash, screenshot, DOM/class, asset, or interaction differs | Stop release; do not update baseline | Static approved interface remains canonical | Preserve candidate/overlay diff and exact route/viewport; owner review only if change is proposed | Recovery and all parity gates | Regression source and guard coverage |
| Performance regression | Any cell > 5,000 ms, 216/216 fails, or resource/API budget regresses >10% | Stop release; retain slow/failure diagnostics | Static canonical runtime remains; optional heavy path can stay disabled | Preserve slowest cells, resource manifests, environment; notify owner | Three complete 72-cell runs and performance budget gate | Bottleneck and representative environment |
| Observability outage | Exporter/sink errors or buffer exhaustion | Isolate exporter; do not fail product logic | Product remains functional; production promotion blocked if monitoring is required | Preserve aggregate dropped count and exporter error class, no payload bodies | Local sink, redaction, failure-isolation tests; exporter smoke | Capacity, retry, sampling, alert ownership |

The release verifier checks that all incidents and required fields remain
present. Commands do not perform destructive rollback or key rotation
automatically.
